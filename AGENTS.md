# Работа AI-разработчика в Path

Рабочая ветка — `paperclip-test`. Перед задачей проверь `git status -sb`, `git branch --show-current` и `git remote -v`. В поставляемой копии нет удалённых репозиториев. Остановись при неожиданной ветке, внешнем remote или конфликтующих локальных изменениях.

Прочитай PROJECT_CONTEXT.md, ARCHITECTURE.md, BACKLOG.md и QA_CHECKLIST.md. Бери одну согласованную задачу. Правь первичные модули, собери результат и воспроизведи сценарий на синтетических данных. В отчёте укажи команды, результат и непроверенные платформы.

Запускай агента в отдельной непривилегированной учётной записи или VM. Дай ему только этот каталог, временный профиль и тестовые данные. На уровне среды запрети исходящие соединения к production. Для первого прогона достаточно полностью отключить сеть. Не передавай домашний каталог владельца, SSH-агент, браузерный профиль, токены GitHub, Supabase и Sites, ключи подписи, экспорт планировщика или доступ к Docker-хосту. Этот файл описывает правила работы, технические ограничения задаёт владелец среды.

Не подключай remote, не отправляй коммиты, не сливай ветку в main. Не входи в реальные аккаунты, не применяй SQL к внешней БД, не подписывай и не публикуй сборки, не запускай установку, удаление или обновление Path на машине владельца. Используй заглушки для сети. Сохраняй локальную историю, миграции и совместимость экспорта. Изменения схем, прав или границ синхронизации выноси на отдельное ревью.
