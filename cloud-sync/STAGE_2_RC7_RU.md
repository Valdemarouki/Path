# Path 2.0 RC7 — ручной тест Cloud Sync

31 октября 2026. Приватная тестовая Windows-сборка. Публичный сайт, Path 1.x и R2-установщик не изменены. Цифровой подписи нет.

## Что готово
В Profile аккаунта появилась кнопка «Синхронизация задач · Тест». После подтверждения отправляются только homeTasks и projects (включая вложенные задачи, описания и существующие поля/ID). Синхронизация не запускается автоматически. Гостевой профиль не отправляется. Notes/Journal, изображения, Canvas, Sport, Calendar и настройки не выбираются для отправки.

Серверная схема и допуск тестового пользователя установлены по подтверждению пользователя. Доступ по реальному Windows JWT пока не проверен. Ограничения auth.uid, OAuth client_id и testers остаются на сервере.

Токен доступа хранится только в памяти main-процесса. Перед истечением обновляется. Refresh token остаётся в зашифрованном Windows vault. Ротация refresh token сохраняется до запроса userinfo, чтобы обрыв этого запроса не терял обновлённую сессию. В renderer токены не передаются.

Локальный checkpoint — источник изменений, в том числе после Undo, импорта и перезапуска. Перед обменом завершаются редакторы/очередь изображений; на время запроса интерфейс блокируется. Пока нет фонового автосохранения в облако: новые изменения отправляются следующим нажатием кнопки.

Запрос записи получает постоянный UUID и ожидаемую серверную ревизию. После потери ответа повтор использует тот же UUID. Подтверждение облака отображается только после успешного ответа и при отсутствии более новых неотправленных изменений.

Перед применением облачных данных сохраняется полная локальная резервная копия. Очередь и журнал незавершённого применения записываются одним атомарным файлом. Повтор различает сбой до и после локального checkpoint. Если после прерванного применения локальные задачи изменились, автоматическая замена запрещена: можно повторить или явно оставить текущую локальную версию с резервной копией.

При конфликте сохраняются оба полных снимка. UI предлагает «Оставить на этом устройстве» / «Использовать облачную версию» с дополнительным подтверждением. Это выбор всего набора задач и проектов, не слияние отдельных полей. Если облако изменилось ещё раз, CAS повторно выявит конфликт.

Применение сохраняет остальные разделы и проходит общую проверку PathRepository. Удаление задачи/проекта, на ID которых ссылаются другие локальные разделы, блокируется (LINKED_DELETE). Связанные данные не удаляются молча. После изменения связей можно повторить; либо выбрать локальную версию. Удаление несвязанных объектов и Undo проверены.

## Файлы
- cloud-sync/session.cjs — координация обмена, единый журнал, восстановление и конфликт.
- desktop/sync-host.cjs — main-process transport, привязка к текущему аккаунту, резервные копии.
- desktop/sync-renderer.js — чтение сохранённого снимка, проверка ссылок, атомарное применение.
- desktop/account-oauth.cjs — проверенный access token в памяти, обновление и ротация refresh token.
- desktop/main.cjs, preload.cjs — ограниченный IPC, блокировка переключения/закрытия при обмене, безопасные коды ошибок.
- desktop/account-renderer.js — кнопки, подтверждение объёма отправки, конфликт, Retry, EN/RU/PL/ES.
- desktop/prepare.cjs, package.json, package-lock.json — включение модулей и RC7.
- desktop/cloud-sync/*.cjs и desktop/app/index.html — сформированные файлы упаковки.
- project-control/check-sync-integration.cjs — новые проверки интеграции.
- project-control/check-account-oauth.cjs, check-account-renderer.cjs — дополнительные проверки авторизации и интерфейса.

## Пройденные проверки
- check-cloud-sync.cjs: настоящая SQL-миграция/RPC в PostgreSQL PGlite, изоляция аккаунтов, client_id/tester, anon/direct-table отказ, CAS, история удаления и идемпотентность.
- check-sync-integration.cjs: два клиента, потерянный ACK, офлайн и перезапуск, конфликт, резервная копия, ошибка диска, сбой до/после применения, новые изменения после сбоя, реальный checkpoint/Undo, сохранность Notes, запрет связанных удалений.
- check-account-oauth.cjs: PKCE, callback, refresh, token isolation/owner check/logout, сбой userinfo после ротации, mock Windows vault.
- check:accounts: профили, host IPC, renderer, перенос гостевых данных.
- desktop check: упакованный HTML, CSP hash, identity, отсутствие inline handlers.
- Сборка Windows x64 Electron/NSIS: установщик собран. Нативная установка/запуск на Windows здесь не выполнялись.

## Что проверить владельцу
1. Установить RC7 поверх RC6, открыть свой аккаунт. Убедиться, что локальные данные на месте.
2. Profile → «Синхронизация задач · Тест» → прочитать объём отправки → «Синхронизировать».
3. Ожидать подтверждённую ревизию. При ошибке сообщить только показанный код (например HTTP_403), не токены.
4. Изменить тестовую задачу, повторить; закрыть/открыть приложение и проверить сохранность.
5. На втором Windows-устройстве войти в тот же аккаунт, не копировать гостевые данные в непустой профиль. Нажать синхронизацию и проверить получение.
6. Проверить офлайн-изменение, восстановить сеть и нажать синхронизацию; конфликт двух устройств; несвязанное удаление; Undo и повтор; другой аккаунт должен получить отказ.

## Не завершено
- Живой Supabase/PostgREST и два реальных Windows-устройства. Локальные HTTP/Electron тесты используют адаптеры; они не доказывают нативную работу.
- Автоматический фоновый обмен и удобный просмотр различий конфликтующих снимков.
- Все остальные разделы, вложения и Shared-доступ.
- Политика хранения истории, серверное резервное копирование/восстановление и нагрузочные проверки для публичного запуска.

RC7 — проверяемый следующий этап, не готовая публичная Cloud Sync. В текущем пакете config.enabled=false означает отсутствие автозапуска; ручной desktop-тест включён только явной командой пользователя и серверным списком тестировщиков.
