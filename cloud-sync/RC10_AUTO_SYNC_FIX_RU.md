# RC10 — автообмен при открытом Profile

Обнаружено: проверка pathSyncIdle блокировала обмен при любом элементе role=dialog, включая само окно Profile. Поэтому наблюдение за статусом мешало запуску автообмена. Этот дефект воспроизведён в скомпилированном приложении. По одному скриншоту нельзя доказать, что он был единственной причиной Local changes pending на компьютере пользователя.

Исправлено: только Profile исключён из блокирующих диалогов. Настоящие редакторы, поля ввода, перетаскивание и несохранённые данные продолжают блокировать применение. Профиль остаётся открытым после получения задач, экран загрузки не появляется.

Дополнительно: стандартные браузерные таймеры вызываются через функции-обёртки, без передачи планировщика в качестве this. Новый тест ждёт реального срабатывания DOM-таймера, а не вызывает tick вручную.

Файлы: desktop/sync-renderer.js, desktop/auto-sync.js, desktop/package.json, desktop/package-lock.json, сформированный desktop/app/index.html, project-control/check-auto-sync-profile.cjs.

PASS: compiled HTML/jsdom — получение при открытом Profile, блокировка настоящего редактора, отсутствие overlay, фактический запуск таймера. PASS: планировщик, повторы, single flight, concurrent edits, idle-safe apply, интеграция очереди/checkpoint/сбоев/конфликтов/backup, упаковка HTML и CSP. Windows x64 NSIS собран с новой иконкой коробки. Нативный запуск и реальный автообмен на Windows здесь не проверялись.

Установить RC10 поверх RC9 на обоих компьютерах. В Profile должна быть кнопка Pause automatic sync (значит включено). Создать задачу, закончить редактирование и дождаться появления на втором компьютере без ручного Sync. Теперь Profile можно оставлять открытым. Если обмен не начинается, нужны статусы с обоих компьютеров.

Данные, серверная схема, Path 1.x и публичный сайт не менялись. Canvas всё ещё локальный. Публикация не выполнялась. Установщик без цифровой подписи.
