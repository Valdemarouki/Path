# Совместные проекты и Canvas

Windows использует существующий вход Path и IPC с проверкой активного профиля. Мобильная версия обращается к тому же RPC через свою сессию. Приватный снимок синхронизации, календарь и исходные заметки в общий объект не входят. Признак общего проекта для карточек и выбора берётся из списка доступных объектов. Владельцу и участникам достаточно подтверждённого аккаунта Path.

## Подготовка отдельного стенда

1. В тестовой PostgreSQL с Supabase Auth примените по порядку `collaboration/schema.sql`, `collaboration/cursor-access.sql` и `collaboration/free-sharing.sql`. На стенде с RC27 примените последние две миграции. Для RC28 достаточно `collaboration/free-sharing.sql`. RPC v2 использует новый закрытый набор таблиц. При наличии данных экспериментального v1 до переключения потребуется отдельная миграция этих данных.
2. Для проверки используйте выделенные тестовые учётные записи. Общий доступ работает и с пустой таблицей подписок. Роль участника определяет доступ к конкретному проекту или доске.
3. Для настоящей отправки писем на сервере запускайте `node collaboration/deliver-invitations.mjs` по расписанию с `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `PATH_INVITE_FROM` и `PATH_JOIN_URL`. Для Resend нужен подтверждённый отправитель. Приглашения доступны в Path независимо от доставки письма. Секреты не входят в клиент. Подтверждённая почта получателя сверяется заново при принятии.
4. Для сайта мобильного приложения примените `python collaboration/prepare_mobile.py --web ПУТЬ_К_КОПИИ_public/app --worker ПУТЬ_К_КОПИИ_worker.mjs --config ПУТЬ_К_КОПИИ_wrangler.json` к исходной мобильной сборке. Пакет поставки уже содержит подготовленные клиентские файлы и worker для проверенной основы. Для нативной сборки используйте соответствующий пакет мобильной ветки.
5. Перед выпуском проверьте на стенде вход по реальной почте, доставку, роли, отзыв и обновление установленного Windows-клиента. Версия кандидата 2.0.0-rc.28. Проверенная подписанная сборка выпускается существующим процессом Windows после принятия изменений.

## Что входит в общий объект

Общие задачи поддерживают название, статус и срок. На доске передаются геометрия, связи, собственный текст и поддерживаемые изображения. Ссылки на личные сущности и неподдерживаемые типы имеют закрытое представление. Личный исходник и его история сохраняются. В списках Path использует ID объекта и роль, а при редактировании проверяет ревизию. Разные поля объединяются, конфликт одного поля сохраняет черновик в форме. Обычный опрос доступных правок происходит каждые 3,5 секунды. Поддерживаются четыре роли, отзыв, выход, адресные приглашения и передача владения другому участнику с его подтверждением.

Проверка базы использует одноразовый PostgreSQL в памяти и синтетические аккаунты. Запуск из корня проекта:

```sh
npm ci --prefix collaboration/qa --include=dev --ignore-scripts
npm test --prefix collaboration/qa
```

## Курсоры на общей доске

После открытия общего Canvas клиент получает одноразовый допуск по действующей сессии Path и подключается по WebSocket к комнате этой доски. Протокол использует координаты самой доски. SVG переводит их в координаты окна каждого участника. Короткое касание экрана показывает указатель примерно на секунду. В меню «Указатели» пользователь может скрыть чужие курсоры или свой. Настройки запоминаются для аккаунта на этом устройстве.

Одна доска поддерживает до 64 одновременных подключений к указателям. Комната CanvasCursorRoom хранит текущие позиции в памяти. При отзыве доступа сервер исключает участника при ближайшей проверке. Сеанс переподтверждается новым билетом через пять минут. База хранит только временные допуски. Ник берётся из метаданных учётной записи. При отсутствии публичного имени показывается «Path · XXXX».

Для стенда разверните изменённый Worker с привязкой CANVAS_ROOMS и миграцией v2-canvas-cursors. Сохраните существующую привязку DEVICES и её миграцию v1. Для другого домена стенда укажите его точный WSS-адрес в настольном клиенте и политиках соединений перед сборкой. При отсутствии сервиса курсоры показывают статус «Указатели не в сети». Редактирование доски использует прежний канал.
