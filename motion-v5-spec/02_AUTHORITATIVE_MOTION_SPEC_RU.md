# PATH 2.0 · Единая спецификация анимаций — Motion Master v5

Версия: **28.10.2026**. Для интеграции Astra в актуальный репозиторий Path 2.0. Приоритет над более ранними Motion v2/v3/v4/v4.1. Демонстрации включены как исполняемые визуальные референсы, но не свидетельствуют о готовности приложения.

## 1. Общая философия движения
**Smooth + Soft Bouncy + Subtle Glow + Physical Response.** Впечатление живого интерфейса создаётся не бесконечной дрожью, а отзывчивой физикой во время действий, мягкой реакцией на успех и редкими локальными деталями. Визуальная система строго чёрно-белая, без золотых/зелёных/синих подсветок, большого bloom и резких вспышек.

Motion — общий сервис для всех вкладок, а не независимый набор CSS-костылей. Рендер не имеет права менять данные или инициировать серверную запись; данные определяют отображаемое состояние. Анимации не блокируют навигацию, ввод, перетаскивание или синхронизацию.

### Режимы
- `Off`: все декоративные motion-эффекты отключены, состояния меняются мгновенно, фокус/hover и семантика сохранены.
- `Subtle` (**по умолчанию**): все описанные здесь утверждённые эффекты, мягкий белый акцент, умеренная амплитуда.
- `Expressive`: допустимо несколько более заметное локальное свечение или пружинный settle, но без изменения пользовательских параметров Wave 4px/1450ms и без агрессивных shake.
- При `prefers-reduced-motion:reduce` системное пожелание имеет приоритет: нет перелёта/волн/глобальных bounce, нет ambient; переходы максимум 80–150мс непространственного изменения (или мгновенно). Не скрывать состояние задачи/выбранной вкладки.

### Общие состояния/правила
`idle → hover → press → release → settle`, а для асинхронного действия также `pending → committed|error`. Hover 140–180мс, подъём 1px, масштаб не более 1.02, слабый glow; Press 80–120мс ~0.93–0.96; settle 250–380мс одной затухающей пружиной. Панели 260–320мс. Не анимировать числа/текст, оси/подписи/курсор ввода и длинные таблицы bounce-эффектом. Использовать transform/opacity, избегать дорогих layout-triggering свойств; анимации высот графиков оптимизировать отдельно.

## 2. Portrait Engine — Living Particle Wave v5

### Структура
- **Единый** `ParticlePortraitLayer` на уровне общего app shell, поверх сменяющегося контента, `pointer-events:none`, не перехватывает клики. Не создавать отдельный JSX-портрет в каждой вкладке одновременно.
- Источники `assets/portraits/*`: **шесть векторных SVG, 516 `<circle>` каждый, `viewBox="0 0 371 486"`**. Исходные файлы неизменяемые. Для нового персонажа потребуется совместимая карта частиц.
- Экранный центр и размер определяются измерением DOM-якорей `portraitAnchor` каждой вкладки (`getBoundingClientRect`, безопасные поля, scroll/resize/DPI), а не хардкодом pixel-left/right. Если old или new anchor не готов, ждать следующего layout кадра, сохранив текущее визуальное состояние.
- Пространственное сопоставление позиций: pairwise minimum-cost matching или равнозначный предрасчёт из исходных SVG. Одинаковый индекс `dot-XXXX` НЕ гарантирует плавную пару. Предвычислить соответствия, не пересчитывать сложную задачу в каждом кадре.

### Что должно видеть глаз
Уходящий бюст Марка Аврелия (или другого философа) не растворяется на месте: небольшая направленная волна проходит по точкам, они **из прежнего якоря** плавно летят в **новый якорь** и по пути собирают черты следующего персонажа. Ни в какой момент не появляется второй наложенный бюст. Нет blackout, резкой смены масштаба и «хаотичного роя».

### Утверждённые параметры
- **Wave amplitude: 4 экранных px** (дефолт первого запуска и Reset to defaults).
- **Wave duration: 1450мс** (дефолт первого запуска и Reset to defaults).
- Дополнительное начало волны разбросано вдоль направления перелёта `0–190мс`, волна обнуляется при начале и конце. Smootherstep/аналогичный ease-in/out, малый либо нулевой overshoot.
- Частицы сохраняют видимость на A→B между двумя портретами. Не более ~9% изменения радиуса в полёте. Не добавлять искусственное сильное свечение или длинные следы.
- Настройки amplitude/duration можно менять через Settings/Profile, но пользовательские изменения сохраняются и НЕ сбрасываются при обновлении версии. Старые умолчания **18px/1250ms отменены**.

### Алгоритм и interruption
1. Snapshot текущего render-state из ровно 516 частиц (`x/y/r/opacity`), включая возможный незаконченный перелёт.
2. Определить новый target-route и его реально измеренный anchor.
3. По spatial correspondence составить 516 пар исходная→целевая позиция.
4. Для частицы i: `q_i=smootherstep(clamp((elapsed−delay_i)/(duration−delay_i)))`, `base_i=lerp(start_i,target_i,q_i)`, поперечное смещение `perp * 4px * sin(pi*q_i)*sin(2*pi*q_i−phase_i)` с нулём на концах. Переход центра и формы синхронный; alpha сохраняется на A→B.
5. При новом маршруте прервать предыдущий transition **из текущих уже отрисованных позиций**. Нельзя «доиграть» старую форму, а затем начинать новую, или прыгать обратно в исходный viewBox.
6. После завершения нормализовать индексы к целевому SVG без визуального смещения.
7. Resize на лету — retarget и пересчёт новых DOM-якорей; временно невидимые якоря не должны создавать огромные координаты.

`VISIBLE/MORPHING/EXITING/ENTERING/NONE/REDUCED_STATIC` — основные состояния портрета. При A→NONE разлёт с fade ~350–550мс, при NONE→B локальная сборка (не выдумывать «предыдущий философ»). При B→B морф не перезапускается. Во время редактирования Notes, подробного Workout, глубокого Progress портрет скрыт.

### Присутствие философов
- **Today Overview → Marcus Aurelius**.
- **Sport Overview → Spartan**.
- **Notes/Journal start/empty → Seneca**, в редакторе скрывается.
- **Progress Overview → Aristotle**, в подробной аналитике скрывается.
- **Habits Overview → философ ещё не выбран**. Старые изображения с Aristotle в Habits НЕ утверждают его: Aristotle закреплён за Progress. В реализации используй `portraitRoute: none` или специальную конфигурационную заглушку без второго портрета до согласования. Не назначай героя самостоятельно.
- **Calendar, Projects, Canvas, Settings → без портрета.** Plato/Socrates — готовые дополнительные ассеты, их маршруты пока не утверждены.

### Ambient — Local Particle Pulses v4 сохранены
Старую анимацию общего масштабирования бюста `scale(...)` на цикле **удалить**. Только иногда одна локально связная группа **4–8** точек (из ближайших в радиусе ~18–26 screen px) мягко увеличивает свои радиусы **1.0→~1.6–1.7→1.0** и слабую яркость, в течение **680–970мс**. Между случайными импульсами **1250–2900мс**, без постоянного света по всей голове. Опциональный медленный дрейф до ~1px для ≤10% точек, если он не добавляет визуального шума. Не делать пульс каждые 60 fps, а использовать одну временную шкалу. Эффект только в VISIBLE; он выключается при входе в morph, скрытии вкладки, снижении производительности, редактировании, Motion Off и Reduced Motion.

**Производительность:** один `requestAnimationFrame` (Canvas2D/WebGL), не 516 независимых React re-render/animation callbacks. Цель 60fps на целевых устройствах, замерить фактически; при просадках сначала отключать дрейф/halo, затем уменьшать stagger/необязательные эффекты. Не считывать 516 DOM-геометрий каждый кадр.

## 3. Today — анимация выполнения задачи

### Path Pulse (`~800мс` hold)
- Hold запускается только на выделенном completion handle. Обычный клик карточки открывает детали; drag через отдельную ручку не запускает hold. Keyboard/screen reader получает обычную доступную кнопку `Complete`, которая не требует удержания.
- `IDLE→HOLDING`: прогресс по контуру, очень слабое сжатие/вибрация ≤0.8px ближе к концу удержания. Отмена на Escape, pointercancel, scroll, drag, длинном выходе за область, уходе со страницы, disabled/read-only.
- `HOLDING→COMMITTING`: **одна idempotent domain mutation**. В режиме offline после записи в локальное durable storage допускается статус `saved locally, pending sync`, но нельзя утверждать, что данные уже загружены в облако.
- `COMMITTING→SUCCESS`: только после подтверждения durable-сохранения (локального либо серверного в зависимости от режима) показывать Done + checkmark spring + локальную волну. Мягкий shockwave визуально затрагивает ближайшие карточки в радиусе **250–320px**, не меняет их реальную раскладку/координаты и не дублирует эффект у других участников команды.
- `ERROR`: откат, понятная ошибка и Retry, без начисления прогресса/повторного выполнения.

### SoftSpringCheckmark (после успешного сохранения)
`0→565ms`: scale **0.28→1.32→0.89→1.055→1**, промежуточные доли **0/35/67/85/100%**, opacity 0→1, вращение от −9° до 0°. Кольцо чекбокса **.83→1.13→.96→1.03→1** за ~540ms. Ни одного двойного bounce. Отмена выполнения → короткий fade/scale out 140–220ms только после подтверждения операции. Не запускать spring заново на React rerender, приходе фоновой синхронизации, обновлении графиков или повторной доставке события; эффект идемпотентно привязан к ID подтверждённой операции.

### Habits / Sport Micro Completion
Для обычного нажатия на привычку/пометки выполненного подхода **300–500ms**, мягкий одноразовый pop/white glow. Нет долгого hold и 250px shockwave для каждого подхода. Полный Path Pulse уместен для **завершения целой тренировки** или настоящей задачи.

## 4. Today — анимация столбиков статистики

`AnimatedMetricBars`: направление изменения **вверх И вниз**; привязка к нижней границе столбиков (`transform-origin:bottom center` либо анимация высоты), **650–800ms, default 760ms**, stagger **25–35ms, default 30ms**. От текущей отрисованной высоты к целевой, без сброса к нулю при обычном повторном открытии вкладки, смене числа в соседней карточке, повторной синхронизации тех же данных или rerender. На cold start разрешено одно спокойное появление, если пользователь не запретил анимации. При частом обновлении target нужно retarget от текущей интерполированной высоты.

Графики не должны показывать фиктивные достижения: счётчики и высоты соответствуют реальным событиям, уникальным ID и выбранному периоду; period boundaries по Europe/Warsaw. Отдельные состояния no-data, zero-data, loading/error. Высота столбика не может выходить за видимую шкалу или уходить в отрицательную высоту. Цифры, оси и текст не bounce, использовать tabular numerals и текстовые альтернативы.

`Progress` использует те же агрегаты/источники данных (и при необходимости такую же спокойную интерполяцию графиков), но не должен копировать миниграфик Today механически.

## 5. Общая навигация и Ionic-колонна

Колонна — последнее утверждённое **отдельное SVG без иконок**. Верхние волюты, тёмный стержень, геометрическое прямое основание — не перерисовывать и не добавлять скруглённое основание. Чистые `24×24` SVG иконки из `assets/navigation/icons` встраивать как **глифы**, их `currentColor` анимировать через один компонент. Home — греческий храм.

**Ровно 8 навигационных вкладок:** Home/Today, Calendar, Projects, Canvas, Sport, Habits, Notes/Journal, Progress. Settings только в Profile в верхней части приложения; не вставлять Settings в колонну. **Один** общий `selectionIndicator` ~420ms ease/spring: непрерывно перемещается между кнопками, сохраняет текущую позицию при быстрой смене. Не использовать одновременно Active SVG со своей нарисованной рамкой и shared indicator — двойной контур. Idle gray; hover ярче, лёгкий 1px lift 140–180ms; press scale .93 ~90ms; active glyph bright, gently filled where appropriate; фокус клавиатуры отдельно виден.

Физический референс колоны `71×375px`; 8 hitbox по 50px = 400px **без** волют и основания. Поэтому не пытаться впихнуть 8 пунктов внутрь 375px: верх и основание оставлять точно как в SVG, **удлинять только модульную центральную часть (shaft)**, адаптировать распределение и размеры контейнера с учётом высоты окна/скролла. Никаких перекрытий, непопадаемых кнопок и контента под основанием.

## 7. Прерывание, async и sync

- Каждая длительная анимация имеет состояние, ID и `cancel/retarget` handler. При смене маршрута, выборе другой цели, resize, destroy unmount — новый target из текущего визуального frame.
- Сохранение данных должно быть независимым от скорости анимации. Ни один эффект не меняет поле completed/metrics напрямую. Только доменное событие меняет данные; эффекты слушают подтверждённый `completed` event, помеченный уникальным operation id.
- Local-first: cloud offline ≠ потеря данных; правильная и честная индикация сохранения и pending sync. При ошибках записи нет ложного успеха.
- В Shared режиме удалённые update events не играют полный личный Path Pulse. Для remote locations сглаживать координаты, но не пересоздавать анимацию при каждом сетевом сообщении.
- Анимации никогда не должны съедать клавиатурный фокус; меню/поповеры должны содержать явный доступный `Close`/ESC.
- Возврат вкладки из фона или восстановление окна: не «накапливать» elapsed frames; завершаем переход согласованно и останавливаем неактуальные loop.

## 8. Производительность и внедрение

1. Сначала определить реальный технологический стек Path 2.0; реализовать одну абстракцию motion tokens + cancel/retarget и типы состояний.
2. Встроить `ParticlePortraitLayer` поверх глобального shell и пути anchor refs.
3. Встроить reusable `SoftSpringCheckmark`, `AnimatedMetricBars`, `PathPulseController`, `SharedNavigationIndicator`, `MotionSettings`, единый Reduced Motion policy.
4. Не дублировать источники правды для Analytics/Calendar/Projects. Не создавать separate mock state для анимаций.
5. Рекомендация: Canvas2D/WebGL для 516 точек с одним rAF вместо сотен React state. В остальных элементах — CSS transforms/WAAPI или motion lib, которая уже есть в проекте, без необходимости переключения всего стека.
6. Измерить actual frame times на целевых устройствах. 60fps — **цель**, не обещанный результат. Деградация должна отключать второстепенные эффекты, а не повреждать данные/удалять важную подсветку статусов.
