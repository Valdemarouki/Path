# Проверка обмена Calendar на Windows и iPhone

Обычные события, созданные через Calendar, передаются между ПК и мобильной версией с датой, временем и важностью. Для двух стартовых записей также передаются важность, название встречи, её время и название дедлайна. Используйте вымышленные данные. Сервер работает на ПК. Доступ имеют устройства, которым ваша сеть и брандмауэр разрешают подключиться к этому порту. Тест хранит отдельную копию на каждом устройстве. Для обмена нужен открытый Calendar хотя бы на несколько секунд.

Для обновления остановите сервер и распакуйте ZIP с заменой файлов прямо в прежнюю папку, где лежит Start.cmd. Существующий calendar-test.sqlite нужен для продолжения того же теста. Откройте вкладки по прежним адресам и обновите их. Если в «Тесте обмена» ещё не появилась строка «События календаря · Время и важность», через несколько секунд обновите страницу ещё раз.

Для проверки только на ПК запустите Start-PC.cmd двойным щелчком и откройте в одном браузере оба адреса из окна сервера. В панели «Тест обмена» обеих вкладок должна появиться одна версия. На ПК нажмите New event, введите название, выберите свободное время и высокую важность, затем нажмите Done. Откройте в мобильном календаре дату события. Карточка должна появиться с указанной важностью ровно один раз, в том числе после перезагрузки.

1. Распакуйте ZIP целиком в свою папку. Если предыдущий тестовый HTTPS-сервер на 8443 ещё работает, остановите его сочетанием Ctrl+C. В Windows запустите Start.cmd. Для запуска нужен Python 3.10+ с командой py и ранее настроенный сертификат для 192.168.1.66. Если IP компьютера изменился, используйте Start.cmd с актуальным IP и соответствующим сертификатом.
2. На ПК откройте https://192.168.1.66:8443/calendar-test/desktop/ в Edge или Chrome. На iPhone откройте https://192.168.1.66:8443/calendar-test/mobile/ в Safari. Используйте обычные вкладки. Если предупреждение о сертификате не исчезло, проверьте адрес и доверие к установленному корневому сертификату.
3. Раскройте «Тест обмена» на обоих устройствах. Дождитесь «Синхронизировано» и «Можно открывать без сети». Сверните панель. В чистой базе встреча назначена на 10:00 по часовому поясу компьютера в день первого запуска.
4. Остановите сервер на ПК. Выключите Wi-Fi и сотовые данные на телефоне. На ПК перенесите встречу на 11:00. На телефоне откройте дедлайн и сохраните новое название. Закройте обе вкладки и заново откройте те же адреса. Проверьте правки, пока связи ещё нет.
5. Запустите Start.cmd из той же папки и верните Wi-Fi. На открытых страницах обмен возобновится автоматически. Можно нажать «Обменять сейчас». На обоих устройствах должны появиться одна встреча в 11:00 и один переименованный дедлайн. Повторное открытие должно показать тот же результат.
6. При разных переименованиях одного дедлайна откройте «Тест обмена», выберите нужное значение, нажмите «Применить выбор».

Сервер хранит тестовую историю в calendar-test.sqlite рядом со Start.cmd. Используйте ту же папку при повторном запуске. Другая база имеет свой идентификатор. Браузер хранит офлайн-копию для конкретного HTTPS-адреса. Удаление данных сайта стирает и его офлайн-правки. Связанные с задачами, сериями и тренировочными записями события используют данные других модулей и находятся за пределами этого теста. При сообщении «Открыта другая тестовая база» запустите обновлённую сборку из папки с исходным calendar-test.sqlite.
