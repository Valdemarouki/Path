# Ручной тест Path Mobile на телефоне — 15–20 минут

Первичная настройка HTTPS/сертификата не входит в эти 15–20 минут. Начинайте прогон в обычной вкладке Safari после успешного phone-check; физическое выполнение ещё не подтверждено.
Выбраны iPhone 12 Pro, Safari, Windows 11 и одна домашняя Wi-Fi-сеть; версия iOS ещё не сообщена. Начинайте после ручной настройки разрешённого HTTPS из [ACCESS.md](ACCESS.md). Этот список — задание для физического iPhone, а не утверждение, что тест уже выполнен. Эмуляция 390×844 CSS px — только ориентир размера, не проверка Safari или настоящей клавиатуры.

Используйте только синтетические записи: заголовки `Phone test`, вымышленные заметки и результаты тренировки. Запишите устройство, ОС, браузер и Build/HEAD из `BUILD.txt` пакета. Не подключайте реальные аккаунты и не импортируйте личные данные.

Основная часть выполняется в **обычном локальном режиме `/`**: desktop-test намеренно ограничивает создание сущностей и Sport. После сохранения нажимайте следующую кнопку, когда исчезнет состояние записи. Если есть ошибка записи, отсутствие Web Locks или конфликт вкладок, не считайте действие успешным; сохраните доступный recovery-черновик перед явным обновлением.

Ориентир — 17–20 минут; подготовка сертификата/USB и первоначального доступа в него не входит. Не выполняйте полную тренировку: значения нужны только для проверки интерфейса.

## Что отметить отдельно

- На iPhone отдельно проверьте обычную и числовую клавиатуру Safari, её закрытие, панель подсказок/autofill, портрет/альбом и область home indicator. Системную полоску приложение не должно рисовать само. Если нет клавиши для скрытия клавиатуры, используйте штатное действие Safari/переход фокуса, не скрывая потерю ввода.
- Возврат после обычного сворачивания и после принудительного закрытия — разные случаи. Если ОС выгрузила вкладку, опишите это; не называйте потерю незаписанного DOM-ввода обычным live-background возвратом.
- Для reduced motion включите системную настройку или Path Motion off и повторите completion: заполнение/смена состояния остаются понятными, большой волны и отталкивания нет.
- Offline B/C — reload или новый запуск без доступа к серверу — не заявлены гарантированными. Не очищайте браузерные данные для «проверки offline»: это другой сценарий, который удаляет хранилище.

В записи экрана оставляйте только синтетический сценарий. Уберите уведомления и вкладки с личной информацией. Не прикладывайте секреты, cookies, ключи сертификата, полный browser profile или содержимое пользовательских записей. Для воспроизведения достаточно тестовых названий и действий.

Для offline A можно после сохранения синтетического ввода временно включить авиарежим и отдельно выключить Wi‑Fi, не перезагружая открытую страницу. Выполните локальную отметку, затем верните домашний Wi‑Fi и перезагрузите страницу. Сначала сохраните незавершённые поля; этот сценарий отличается от потери внешнего Internet при доступном локальном сервере.
