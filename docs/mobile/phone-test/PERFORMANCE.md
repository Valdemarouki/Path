# Производительность и offline: проверенные условия и границы

Проверка выполнена в Linux Chromium headless, viewport **390 × 844 CSS px**, DPR **1**, без CPU throttling, на существующем loopback-сервере `127.0.0.1:8010`. Это не измерение iPhone, Android, Safari или физической экранной клавиатуры. На хосте могли выполняться другие задачи; показатели не являются обещанием одинаковой плавности на телефонах.

## Воспроизводимые синтетические данные

[phone-fixtures.mjs](../../../mobile/tests/phone-fixtures.mjs) создаёт валидный native-state без чтения существующего browser profile:

| Набор | События одного дня | Заметки | Сериализованный размер |
| --- | ---: | ---: | ---: |
| normal | 24 | 32 | 31 132 bytes |
| large | 400 | 400 | 721 591 bytes |

События и заметки имеют постоянные синтетические ID и дату `2026-11-11`. Увеличенный набор намеренно содержит 400 событий одного дня: это нагрузочный сценарий, а не описание обычного дня пользователя. Дата фиксируется отдельно от таймеров; `requestAnimationFrame`, `setTimeout` и `setInterval` остаются нативными.

[phone-performance.cjs](../../../mobile/tests/phone-performance.cjs) не запускает сервер, не открывает порт, не создаёт tunnel и не меняет firewall. Он требует уже доступный разрешённый локальный сервер:

```bash
MOBILE_PHONE_PERFORMANCE_EVIDENCE=/tmp/path-phone-performance \
  node mobile/tests/phone-performance.cjs
```

## Результат доступных проверок

**7 focused-групп PASS**: обычный/увеличенный набор и пять проверок различий offline/восстановления. Данные: `/tmp/path-phone-performance-final/{normal,large,verification}.json`; итоговые копии evidence включает основной отчёт этапа.

| Показатель | normal | large |
| --- | ---: | ---: |
| Calendar: команда смены hash → два RAF, два захода | 63,3 / 46,1 ms | 107,2 / 99,2 ms |
| Notes: команда смены hash → два RAF, два захода | 44,7 / 30,7 ms | 65,4 / 64,6 ms |
| Calendar scroll: p95 / max frame gap | 16,8 / 16,8 ms | 16,8 / 16,8 ms |
| Notes scroll: p95 / max frame gap | 16,8 / 16,8 ms | 16,7 / 16,8 ms |
| Scroll frame gaps > 50 ms | 0 | 0 |
| DOM на прогретом Notes до/после циклов | 437 → 437 | 1909 → 1909 |
| Обработчики window/document/documentElement | 68 → 68 | 68 → 68 |
| Запущенные IMPACT-анимации / visual layers | 5 / 1 | 5 / 1 |
| RAF / timeouts после успокоения | 0 / 0 | 0 / 0 |

Прокрутка — 75 программных RAF-шагов по 22 CSS px. Это измерение browser frame gaps, не физической touch latency и не гарантия 60 FPS на iPhone с DPR 3. Смена вкладки включает browser automation command и два кадровых callback, а не изолированное время JavaScript-функции. На итоговом large обнаружены long tasks 52–86 ms при смене/перестроении экранов: рендер больших списков имеет заметную стоимость, даже если последующая прокрутка не показала пропусков в этой среде. Виртуализация списка и уменьшение объёма данных не внедрялись автоматически.

### Узкая оптимизация подтверждённого hotspot

В ходе профилирования найдены повторные создания `Intl.DateTimeFormat`: в app time-formatting и в [calendar-model.mjs:zoneParts](../../../mobile/calendar-model.mjs). Добавлены два ограниченных кеша formatter-объектов, до 32 записей каждый, с ключами языка/типа/зоны либо зоны. Результаты преобразования дат не кешируются; источник timezone и DST-семантика не меняются. Навигация, blur/noise и IMPACT не упрощались.

| Нагрузка large | До кешей | Только app-cache | Итог: app + zoneParts cache |
| --- | ---: | ---: | ---: |
| Calendar, два захода | 147,4 / 249,1 ms | 122,7 / 115,2 ms | 107,2 / 99,2 ms |
| Создания DateTimeFormat за Calendar render | Не инструментировались | 402 / 402 | 3 / 2 |
| Notes, два захода | 81,6 / 132,5 ms | 65,2 / 64,9 ms | 65,4 / 64,6 ms |

Счётчик использует прозрачный Proxy над конструктором в синтетическом профиле; до кешей число конструкторов не измерялось, поэтому source-count не выдаётся за измерение. Сравнение описывает эти три запуска и не доказывает универсальное ускорение: normal timings из-за host/command/scheduling вариации не улучшились во всех наблюдениях. Сохранены `/tmp/path-phone-performance-before-formatter-cache`, `/tmp/path-phone-performance-after-formatter-cache` и `/tmp/path-phone-performance-final/BEFORE_AFTER.json`.

Проверены шесть циклов раскрытия/закрытия панели и шесть открытий/отмен числового selector. Сравнение проводится после первого открытия singleton-редактора: сохранение одного закрытого form DOM — ограниченный повторно используемый кеш, не накопление при каждом открытии. После действий не накапливаются отслеживаемые глобальные обработчики, DOM, transient layers, running animations или RAF. Это не heap/GC-профилирование и не учёт каждого browser-internal listener.

В спокойном состоянии остаётся только периодический **30 s** таймер текущей даты/события. Фоновый **1 s** таймер Sport при отсутствии видимого активного Sport больше не работает. Наличие намеренного clock-таймера не трактуется как постоянный animation loop. Нативный RAF sampler проверяет собственную работоспособность: до lifecycle-сравнения зарегистрировано больше 150 реальных callback.

Материал сохраняется: один navigation backdrop blur 14 px, статичный noise на navigation с opacity `.009`; непрозрачные event cards не имеют backdrop blur, их статичный noise имеет opacity `.024`. Источники: [navigation.css](../../../mobile/navigation.css), [calendar-cards.css](../../../mobile/calendar-cards.css), общий [panel-noise.svg](../../../mobile/assets/panel-noise.svg). Анимации Path не удалялись ради показателей. Нагрузка GPU, расход батареи и raster memory физического Safari здесь не измерены.

## Offline: три разных сценария

| Сценарий | Доступный результат |
| --- | --- |
| A. Полностью загруженная страница, затем вся сеть недоступна | Создание тестовой задачи и локальная запись прошли. Уже загруженный код работает с localStorage; новое сетевое чтение fixture не обещается |
| B. Reload, сервер приложения недоступен, HTTP cache очищен/отключён | Запуск не прошёл: `ERR_INTERNET_DISCONNECTED`; service worker отсутствует |
| C. Предыдущая вкладка закрыта, новая открывается без сети и без кеша | Запуск не прошёл: `ERR_INTERNET_DISCONNECTED`; это новая страница, не физическое завершение процесса iOS |
| Публичный Internet недоступен, но разрешённый локальный сервер остаётся доступен | Reload и новая страница прошли при блокировке всех внешних hosts: код, стили, шрифты и assets локальные |

После неудачных B/C возвращение сети восстановило исходную локальную запись побайтно; созданная в A задача сохранилась. Отказ запуска не удалял localStorage. Наличие данных не предоставляет HTML/JS для offline-старта. Случайный HTTP cache или восстановление страницы из памяти браузера не являются гарантированным контрактом запуска.

Эти положительные проверки выполнялись на loopback secure context с доступными Web Locks. Они не доказывают возможность записи через обычный `http://<LAN-IP>` на телефоне; выбор безопасного способа доступа описан отдельно в инструкции этапа. Никакой новый сетевой доступ в ходе проверки не создавался.

## Отдельное предложение перед offline reload/cold start

Для гарантированного B/C требуется отдельно согласовать PWA/service worker либо иной локальный пакет: allowlist статических ресурсов и синтетических fixtures, версионирование кеша, атомарное обновление/rollback и явные правила активации при открытом редакторе/тренировке. Кеш приложения должен оставаться отдельным от предметных записей. Систему установки, обновления и кеширования в этом этапе не внедряли.
