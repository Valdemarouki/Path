Проверено 11 ноября 2026, Europe/Warsaw. Источник — desktop-файлы в существующей `/workspace/Path` на исходном HEAD `55f7ff8290fcc8be39e3d05f5dbaf293e441b42a`. Desktop только читался. Хеши и ссылки на функции — [SOURCES.json](SOURCES.json). Это контракт доступного снимка, не утверждение о непроверенной production-версии.

## Что является фактом

Desktop пользовательский backup: `{format:'path-checkpoint',version:2,state}` — [privacy-export.js](../../../privacy-export.js), `pathBackupState`. Private Journal исключается по умолчанию и включается отдельным выбором. В синтетическом наборе Journal включён намеренно и не содержит персональных записей.

Локальный repository checkpoint добавляет `revision`, `undo`, `redo`; [storage.js](../../../storage.js), `pathCheckpointEncode/Decode`, дедуплицирует встроенные image/file payloads через `imageCodec` 1/2, `imageAssets`, `{pathImageAsset:index}`. История, пулы и неизвестные свойства сохраняются полностью, не исполняются и не устанавливаются в mobile repository.

Обязательные корневые массивы desktop: homeTasks/habits/projects/canvases/workouts/events и объект settings. Notes/workoutRecords/programs/eventSeries и дополнительные коллекции могут отсутствовать. Отсутствующие массивы не дописываются в оригинал. Desktop default `createdAt` — epoch milliseconds; live Mobile schema 5 ожидает ISO. Preview сохраняет исходный тип, не вызывает `migrate` и не создаёт schemaVersion.

В таблице «редактируется» означает **перечисленные операции над изолированной копией с полным исходником**, а не готовность установить весь desktop-state в рабочий Mobile.

## Identity and absence rules

- Desktop's task IDs are globally unique across home and projects. Other entity kinds can reuse the same string: verified by the actual desktop validator and a cross-entity fixture test. References must carry entity kind; node IDs remain board-scoped. No ID remapping is performed.
- Raw low-level `stageDesktopCheckpoint` remains a lossless container function. Its older toy tests intentionally preserve structurally ambiguous documents; **that is not desktop domain validation**. The new preflight/view adds actual task-identity, relationship and time checks before allowing edits.
- Missing properties stay missing; null/false/0/empty strings remain distinct. `completedAt:null` on an explicit undo is desktop operation semantics, not a migration default. Unknown fields stay in the canonical document at all depths; projections are never written wholesale over source records.
- Repeated reads/round-trips never append. Setting the same task completion twice preserves its original completedAt. Native JSON parsing is supplemented with duplicate-key and lossy-number rejection; an imprecise numeric literal is not silently accepted.
- Date-only fields remain strings. No `new Date(civil).toISOString()` conversion rewrites them. Time edits use the source's explicit event zone/fold; no environment timezone inference for unzoned events.

## Validation boundaries

Browser input: UTF-8 JSON ≤8 MiB, ≤250000 JSON values, depth ≤64; unsafe keys/accessors/non-JSON objects rejected. The desktop parser has a 64 MiB limit; the **smaller preview limit is deliberate**, not a claim that larger desktop files are corrupt. No chunked or large-asset importer was added.

Preflight covers mapped required fields/types, identity scopes, references, dependency cycles, calendar wall/instant consistency, recurrence, habit history, workout snapshots/set identity and embedded asset references. It reports unknown enums as opaque instead of substituting a supported value. Missing live references block projection; an absent historical template/session with a retained snapshot is a warning, not automatic repair.

This mobile preflight is **not a complete replacement for every desktop pathValidate rule**. Full history replay, activeFocus, exercisePreferences, skillTests and program schedule configuration remain named opaque scopes. They are retained, not activated. Actual desktop `pathValidate`/codec are run only on synthetic data in a VM as a test oracle; no desktop app, store, credentials or services are started.

## Proposals before activation or synchronization — not implemented

No desktop change is required for the current reversible view and tested copy edits. Before a real importer/common server:

1. Define an explicit versioned activation boundary. Reconcile numeric createdAt, zero/fractional task duration, missing legacy dates and advanced habit/Sport rules without silently applying live mobile defaults.
2. Use entity-kind-aware references; retain source IDs. Review mobile's stricter ID creation assumptions rather than renaming valid desktop objects.
3. A persisted Main Task reference requires a confirmed desktop field/export contract. Potential future source locations: `privacy-export.js` and the actual desktop task-selection owner. The inspected snapshot does not supply that owner; no fictitious mapping is implemented.
4. If legacy events lack zones, desktop could export explicit per-event zone/fold/instants after a user-confirmed interpretation, plus version/source metadata. Export-time machine zone alone cannot prove the original event zone.
5. Agree recurrence/exception editing, snapshot/attachment delivery, deletion/tombstones, revision/operation idempotency/conflicts, private Journal and ACL before connecting an account. Preserved local revision/undo/redo are not a server operation log.

These are integration proposals, separate from the confirmed field map. No desktop files were edited and no server/account/outbox was connected.
