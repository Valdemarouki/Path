## Что работает

- День Calendar: события выбранной даты в хронологическом порядке, date-only deadlines первыми, устойчивый порядок равных времён по ID; сегодня/соседние даты; пустое состояние. Межсуточные интервалы явно подписывают обе даты. Положение/высота событий не имитируют timeline: это адаптивный дневной список.
- Один компактный редактор событий через New event/нажатие карточки/Enter/Space. Task Quick Add остаётся прежним; конкурирующий event composer не добавлен.
- Название, описание, место, дата/начало, elapsed duration либо явные дата/время окончания. Изменение конца пересчитывает duration; изменение начала/duration пересчитывает конец. Переход через полночь требует явной следующей даты. DST gap отвергается, повторное время начала/конца имеет явный выбор earlier/later. Зона события видна и сохраняется.
- Типы `busy/workout/routine/deadline/focus/free_time`, важность `none/low/medium/high`, дополнительные иконки desktop. Тип и важность не подменяют друг друга. Название → время → тип/важность; все мелкие controls/текст Manrope 400.
- Редактирование/перенос сохраняют ID и дополнительные поля. Выполнение/отмена обычного события отражается после reload и отдельно от важности. Обычный tap/scroll ничего не завершает; long press не добавлен.
- Явное удаление с подтверждением только самостоятельного поддерживаемого события. Dirty-поля сначала нужно сохранить или отбросить. Undo восстанавливает точный ID/содержимое и переживает reload. Показываются название/время восстанавливаемого события, чтобы после загрузки данных другой вкладки не скрывать смену цели Undo.
- Ошибки записи не закрывают редактор и не сообщают ложный успех; ввод остаётся для retry. На время ожидающего lock Save поля заблокированы, чтобы ввод после снимка сохранения не потерялся при закрытии. Двойной Save не создаёт копий.
- Устаревшая вкладка не пишет поверх новой версии. Явный Load latest сохраняет форму и показывает актуальную версию для сравнения перед сохранением своего варианта. Нет автоматического слияния.
- Фокус возвращается к карточке/выбору даты; после удаления — к Undo. Блок восстановления находится в потоке страницы, не перекрывает Calendar/навигацию. В раскрытой сетке он невидим и inert, сохраняя высоту — контент за панелью не сдвигается.

Исправления, подтверждённые проверками: NaN-сортировка дедлайнов без instants; ложный запрос overlap при изменении одного названия уже пересекающегося события; защита входящих `activeWorkout/workoutRecords.sessionId`; отсутствие устаревшего Saved после отказа следующего действия; очистка временного интервала/выполнения при явном переводе обычного события в date-only deadline.

## Данные, Undo и ограничения

Мобильный namespace прежний: `path-mobile-alpha-v1`. Текущая `schemaVersion:4`; миграции 1/2/3 происходят в клоне в памяти и идемпотентны. На диске старые bytes не меняются до успешного пользовательского commit. Неизвестные поля/коллекции остаются в клоне; события и ID не пересоздаются. Повреждённый/будущий формат не перезаписывается fixture-данными. Совпадение старого неизвестного ключа с неподдерживаемой версией нового undo metadata приводит к отказу открытия, не потере исходной записи.

`mobileEventUndo{version:1,index,event}` — мобильный локальный буфер последнего удаления, не desktop-field, cloud tombstone или общая корзина. Удаление + снимок и восстановление + очистка буфера — по одному сохранению одного документа. Следующее удаление заменяет буфер. Снимок, включая описание, входит в mobile JSON export и хранится до восстановления/следующего удаления/очистки браузерного хранилища. При ID collision восстановление блокируется без перезаписи существующего объекта; при полном списке/ошибке квоты снимок остаётся. Undo возвращает исходное событие без автоматического перемещения других бронирований; изменившееся расписание может содержать пересечения.

Web Locks сериализуют сотрудничающие вкладки этого приложения; exact baseline comparison отвергает устаревшую запись. Это реальная локальная координация, но не distributed merge и не защита от старого клиента/DevTools, обходящего lock. Без Web Locks редактирование блокируется. Сохранность вне браузера/этой среды не гарантируется.

Повторения/исключения, исходящие links/snapshots и входящие workout session links — read-only, без редактирования и удаления. Их ID/series/cancelledDates/snapshots доступны в сведениях. Не удаляем связанную задачу, тренировку, проект или серию. Неизвестные enum/fold/неподдерживаемые значения показываются исходными, не незаметным default в select.

Free Time: мягкая/защищённая бронь, none importance, incomplete; protected блокирует новые интервалы. Никакого автоматического перепланирования. Deadline — дата/hour0/duration0, без completion control/Upcoming. Legacy несовместимые свойства защищены read-only. Reminder сохраняется/показывается, но уведомления на телефоне не доставляются. Полного desktop import, live sync/accounts, recurrence editing, open-slot suggestions и полноценного offline shell нет. Выбранная дата — локальное состояние экрана; reload возвращает её к текущему дню, сами события сохраняются.

Все прочие разделы оставлены на прежнем уровне; их дальнейшая совместимость описана в аудите. Не добавлены shared/, root-конфигурации, новые зависимости или lockfiles.

## Запуск и повторение проверок

Python 3 и современный браузер с Web Locks/localStorage достаточны для приложения:

```sh
cd /workspace/Path
python3 mobile/build.py
python3 -m http.server 8010 --bind 127.0.0.1 --directory mobile/dist
```

Открыть http://127.0.0.1:8010 на той же машине; остановить Ctrl+C. ES modules требуют HTTP, не file://. На Windows распаковать архив, открыть PowerShell в папке с mobile/ и использовать `py -3` вместо python3. Это локальный server, не deployment.

Существующие Playwright/Chromium/FFmpeg нужны только для тестов, fontTools — для font verification. Для всех тестов, включая историческое typography preview:

```sh
# Отдельный терминал для второго локального сервера:
python3 mobile/typography-preview/build.py
python3 -m http.server 8020 --bind 127.0.0.1 --directory mobile/typography-preview/dist
# При запущенных 8010 и 8020:
node mobile/tests/run-polish.cjs --evidence /tmp/path-calendar-polish-release --with-typography
# Сфокусированные проверки:
TZ=Europe/Warsaw node --test mobile/tests/*.test.mjs
node mobile/tests/calendar-polish.cjs
```

## Передача и дальнейшие шаги

`python3 mobile/package.py` теперь создаёт source archive, Git bundle и SHA256SUMS **вне репозитория**, по умолчанию в соседней `path-mobile-deliveries/<HEAD>/`. Можно указать `--output-dir /workspace/path-mobile-deliveries/<unique-name>`. Source содержит committed mobile/ и docs/mobile/, bundle — локальную feature-ветку с её историей. Проверить SHA256, `git bundle verify`, распаковку/сборку и восстановленный HEAD. Browser localStorage не входит в Git bundle; для него отдельный JSON export Settings. Архивы не доказывают скачивание или внешнюю резервную копию. В чате не подтверждён инструмент выдачи downloadable attachments.
