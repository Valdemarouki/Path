## Ограничения границы данных и будущий контракт

Подтверждено: desktop проверяет уникальность ID внутри коллекций; mobile пока проверяет общую уникальность homeTasks/events/habits. Desktop createdAt — число, mobile — ISO; диапазоны дат и части валидаторов различаются. Поэтому нет обещания, что любой desktop backup напрямую откроется в mobile. Нельзя устранять коллизии переназначением существующих ID. Будущий адаптер должен использовать identity `(workspace, entityType, id)`, согласовать caps/versions и проверить golden round-trips до реальной синхронизации.

Уже пригодны для будущего контракта: стабильные entity IDs, известные enum, абсолютные instants + IANA zone/fold, сохранение extension fields, отсутствие молчаливой подмены linked entities. Пока только локальные решения: Web Locks и baseline comparison (координация сотрудничающих вкладок данного браузера), mobileEventUndo и localStorage. Это не distributed conflict resolution и не серверные tombstones. Undo восстанавливает исходное событие без автоматического перепланирования чужих записей, даже если расписание за это время изменилось.

Предложения (не реализованы): versioned import/export adapter; transactional outbox/idempotency key; server revision/conflict protocol; separate attachment transport/ACL; серия/исключения как атомарная группа; отдельные device preferences. [Предыдущий sync proposal](../compatibility/SYNC_PROPOSAL.md) остаётся предложением, не свидетельством работающего backend. Общие аккаунты, Personal/Shared-права, real sync и полноценный offline shell не подключены.
