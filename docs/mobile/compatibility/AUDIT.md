## ID, версия и границы совместимости

В original.html uid() использует Math.random().toString(36).slice(2,10): это короткие локальные ID без подтверждённой глобальной гарантии. Нельзя переназначать уже существующие ID; для будущего sync нужна область workspace/entity и выявление коллизий. Canvas edges содержат from/to, directed, fromSide/toSide (left/right/top/bottom), label (storage.js).

Существующие ID рассматриваются как непрозрачные строки, сохраняются без переназначения. Мобильные новые ID — crypto.randomUUID. При будущей синхронизации нужны аудит глобальной уникальности/области ID, явная карта ownership и synthetic task-deadline ID. По одному локальному снимку нельзя подтвердить глобальную уникальность или готовность sync.

Мобильная schemaVersion 3 обозначает календарный контракт (включая deadline duration 0). Версии 1/2 мигрируются в памяти: v1 получает прежнюю mainTasks-ссылку, v2→v3 меняет только номер схемы. События, ID, неизвестные свойства и коллекции не переписываются. Нет необходимости писать данные при загрузке: запись версии 3 происходит только при успешном пользовательском сохранении. Старым клиентам нельзя продолжать запись версии 3; они должны отказать в открытии без перезаписи. Все неизвестные ключи/коллекции сохраняются structuredClone + ограниченным patch. Это не полноценный desktop importer: desktop root и расширенные Habits требуют отдельного адаптера и проверки.

Дополнительные факты для будущего адаптера: home.js допускает отсутствующую task.date и использует дату data.createdAt; mobile требует явную date. Desktop pathEmpty хранит createdAt как Date.now(), mobile createdAt — ISO-строка. Это ещё две причины не принимать desktop-root напрямую текущим мобильным валидатором. Notes body — Markdown с live rich-представлением, не сохранённый HTML; visibility private и date/journalDate принадлежат реальной модели Journal, а не новому мобильному формату.
