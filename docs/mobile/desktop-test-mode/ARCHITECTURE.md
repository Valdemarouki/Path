# Изолированный desktop test mode: границы и источник данных

> Обновление 11 ноября 2026: поддержка completion и ручных привычек расширена в [Desktop actions](../desktop-actions/REPORT.md). Ограничения действий ниже описывают предыдущий этап; определения исходных полей и канонического хранения сохраняют силу.
Этап интегрирует подготовленные синтетические desktop checkpoints в существующее мобильное приложение. Это режим проверки совместимости без аккаунта, Personal/Shared, сервера или облачной синхронизации. Предыдущий [подтверждённый контракт](../data-compatibility/CONTRACT.md) продолжает действовать; сохранность полного объекта не означает возможность редактировать каждое его свойство.

## Вход и пространство хранения

Обычный запуск и `?desktop-test=1` используют один [app.mjs](../../../mobile/app.mjs), тот же DOM приложения, навигацию, карточки, существующие редакторы и числовые селекторы. Параметр выбирает репозиторий до первого чтения данных:

| Режим | Репозиторий | localStorage key |
| --- | --- | --- |
| Обычный мобильный | `createRepository` из [model.mjs](../../../mobile/model.mjs) | `path-mobile-alpha-v1` |
| Синтетический desktop | `createDesktopTestRepository` из [desktop-test-repository.mjs](../../../mobile/desktop-test-repository.mjs) | `path-mobile-desktop-test-v1` |

Импорт модулей не активирует другой репозиторий. Test mode не вызывает native `createRepository`, не читает его записи и не выполняет native schema migration над desktop checkpoint. Обычный режим не активирует тестовое хранилище. Ссылка в Settings открывает test mode; компактная пометка «Тестовые данные» и действие выхода присутствуют на всех его экранах.

[desktop-test-controls.mjs](../../../mobile/desktop-test-controls.mjs) загружает только два фиксированных локальных пути: plain `desktop-v2.json` и pooled `desktop-pooled-v2.json` из [существующих fixtures](../../../mobile/compatibility-preview/fixtures/). File picker реального экспорта отсутствует. CSP разрешает same-origin загрузку этих ресурсов; внешние источники для этого режима не нужны.

Каждая загрузка создаёт новую тестовую копию с новым внутренним ID. Ранее изменённая копия не заменяется; её можно снова выбрать в списке. ID самой копии служит внутренним контекстом, не становится ID desktop-сущности и не попадает в desktop-экспорт. Поддерживается не более 12 копий и 8 MiB суммарного сериализованного namespace. Ошибка лимита не удаляет предыдущие копии.

## Каноническая запись и экранная проекция

Один сериализованный test root содержит `format/version`, общую `revision`, `activeDatasetId` и `datasets[]`. Для каждого набора сохраняются:

- `original`: полный первоначальный desktop envelope;
- `current`: полный изменённый desktop envelope, единственный источник редактируемых предметных данных;
- `prefs`: язык, motion и ссылки главной задачи только для этой копии;
- внутренние ID, дата создания и revision набора.

`original/current` включают необработанные свойства, revision/undo/redo, asset pool, вложения и неподдерживаемые структуры. Репозиторий не создаёт отдельные сохранённые задачи для Today, Calendar и Projects.

Получение `.state` строит одноразовую проекцию для действующих UI-компонентов через существующие `desktopToMobileView` и domain preflight из [desktop-adapter.mjs](../../../mobile/desktop-adapter.mjs), [desktop-inspector.mjs](../../../mobile/desktop-inspector.mjs). Экранные defaults — например служебный `readOnly`, отсутствующие коллекции для безопасного обхода UI и вычисленные instants явной зоны — принадлежат проекции, не `current`.

Главная задача является `prefs.mainTasks[date]`, а не выдуманным desktop-полем. Ссылка проверяется по реальной задаче и её доступности для дня; отсутствующая, архивная или недоступная ссылка исключается из проекции. Desktop-экспорт от выбора main не изменяется.

## Точечное изменение

Существующий редактор передаёт обычный callback изменения состояния. Test repository:

1. Строит текущую проекцию и отдаёт callback отдельный clone.
2. Сравнивает изменённую проекцию с исходной.
3. Переводит разрешённые различия в уже существующие команды `applyDesktopEdit`: `eventTitle`, `eventTime`, `eventImportance`, `taskCompletion`, `noteBody`.
4. Применяет команды к полному `current`, повторно проверяя возможности по каноническому источнику.
5. Строит ожидаемую проекцию результата. Любое неразрешённое дополнительное отличие отклоняет всю операцию.
6. Только после успешного `localStorage.setItem` заменяет кеш репозитория и обновляет экраны.

Проекция не сериализуется поверх полной desktop-записи. Изменения нескольких полей атомарны: если последняя команда или запись завершилась ошибкой, предыдущие команды остаются только в локальном временном расчёте. UI не получает ложного успешного завершения. Неизвестные свойства и неотображаемые поля не очищаются при сохранении формы.

## Подтверждённые ограничения

| Раздел | Доступные действия | Сохраняемые ограничения |
| --- | --- | --- |
| Today / Tasks | Completion/undo поддерживаемой домашней или проектной задачи; выбор main как prefs | Поля задачи доступны для просмотра. `0`, дробные значения и отсутствие duration сохраняются точно; ограниченный integer selector не округляет их |
| Calendar | Title/time/importance самостоятельного события по capabilities адаптера | Тип, completion, notes/location/icon/protected, linked/history/recurrence и удаление не редактируются. Native completion/IMPACT в обычном режиме остаётся прежним |
| Projects | Существующая структура, task rows, проценты; completion/undo поддерживаемого child task | Статусы проекта, зависимости, milestones, Gantt и создание/удаление остаются вне текущего адаптера |
| Notes | Body поддерживаемого Markdown через существующий редактор | Title/metadata не меняются этой операцией. Вложения и будущие blocks доступны для просмотра; преобразования в plain text нет |
| Habits | Реальные schedules, dated values/checkIns, exceptions и полный исходник | Нет ложной активации weekly/count/duration/sport-source правил или кнопок отметки |
| Sport | Templates, плановые snapshots, completed records и фактические значения | Нет редактирования snapshots, активной сессии, результатов, повторного планирования или смешения reps/kg |
| Canvas | Поддерживаемый просмотр; для сложной/grouped доски — исходные узлы, связи, геометрия с объяснением | Граф не flatten, координаты и collapsed state не переписываются. Просмотр исходной структуры не равен полному Canvas-редактору |
| Progress | Реальные записи task completion, confirmed focus, workout history и привычек; существующий процент проектов | Неподдерживаемая или отсутствующая история не превращается в достоверный нулевой результат; новые метрики не изобретаются |

Идентичность capabilities задаётся типом сущности, `projectId` при необходимости и исходным `id`; набор добавляет внешний контекст. Task IDs остаются уникальными среди home/project tasks. Одинаковые строки ID у разных видов сущностей допустимы и не требуют переименования.

## Время и даты

В изученном [timezone.js](../../../timezone.js), `pathEventTiming` использует явную `event.tzid` либо текущую системную зону desktop при её отсутствии; `pathStampEvent` может затем записать zone/fold/instants. Это подтверждает desktop fallback, но не доказывает историческую зону отдельно экспортированной legacy-записи.

Test mode не переносит это предположение на другую машину: у unzoned-события сохраняются исходные civil date/hour/duration, зона не подставляется. Временные поля редактора блокируются с объяснением. При наличии такой неоднозначной записи в общей timeline retime других событий тоже ограничен, поскольку адаптер не может достоверно проверить интервалы/overlap. Поддерживаемые metadata-only операции по-прежнему сохраняют оригинал.

Явно зонированные карточки показывают source-zone wall time и source civil day; дата deadline остаётся строкой без преобразования в UTC. На простое открытие/закрытие редактора не приходится ни migration, ни запись defaults.

## Конфликт, сбой и восстановление

Все операции приложения используют Web Locks с отдельным test key. Репозиторий дополнительно сравнивает последнюю прочитанную строку namespace с текущей непосредственно перед сохранением, включая no-op/select. `storage` event сообщает об изменении другой вкладкой. Устаревшая вкладка блокирует запись; более новое содержимое не перезаписывается.

Это обнаружение конфликта, не merge и не полноценный resolver. Черновик формы остаётся видимым. Действие сохранения recovery-копии выгружает текущий кешированный desktop source, сохранённую строку test namespace и поля открытых test-редакторов. Оно не читает обычное мобильное хранилище и не применяет recovery автоматически. Пользователь может сохранить материал, затем явно обновить данные. Ошибочный fixture, повреждённый namespace или quota failure не заменяет последний рабочий кеш; повреждённый исходный namespace не сбрасывается молча.

## Экспорт и проверка

`exportDesktop()` проходит через `mobileViewToDesktop` полного `current`. `reportChanges()` сравнивает `original/current` и выдаёт JSON Pointer, тип/ID объекта, поле, before/after и признаки наличия свойства. В отчёте различаются отсутствие поля, `null`, `0` и пустая строка.

Экспорт — новый скачанный файл. Он не записывается в desktop repository и не запускает desktop import UI. [Изолированный oracle](../../../mobile/tests/desktop-oracle.mjs) используется только тестами: pure desktop codec/validator читают синтетический JSON в VM без запуска приложения или его хранилища.

## Пределы сохранности

localStorage принадлежит конкретному browser profile и origin, включая порт. Выход в обычный режим не удаляет test namespace; повторный вход и reload читают его снова. Очистка браузерных данных, приватная сессия, смена origin/порта или утрата среды могут сделать эти записи недоступными. Local commit, namespace и файлы внутри облачной среды не являются внешней резервной копией. Восстановление из архива/bundle нужно проверять отдельно; пользовательские данные для этого этапа не используются.
