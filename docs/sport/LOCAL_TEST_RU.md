# Path Sport — локальная проверка на Windows и iPhone

Готовый ZIP содержит собранные `Path-Desktop` и `Path-Mobile`, HTTPS-helper для
телефона в `Tools` и локальные шрифты/ассеты. Для запуска готовой сборки Node/npm и повторная
установка зависимостей не нужны. Нужен существующий Python 3.10 или новее и браузер.
Ничего не устанавливается в рабочую Windows-версию Path. Используйте синтетические
данные; не импортируйте рабочие резервные копии.

## Компьютер: desktop-интерфейс

1. Распакуйте ZIP, например в `C:\Path-Sport-Test`.
2. Убедитесь, что есть `C:\Path-Sport-Test\Path-Desktop\index.html`.
3. Откройте обычный PowerShell и выполните команды по одной:

```powershell
Set-Location C:\Path-Sport-Test
```

```powershell
py -3 -m http.server 8020 --bind 127.0.0.1 --directory Path-Desktop
```

4. Оставьте окно открытым и перейдите на компьютере по адресу
   `http://127.0.0.1:8020/`. Это loopback; firewall открывать не требуется.
5. Выберите Sport. Проверяйте редактор, библиотеку и расписание на отдельном
   тестовом origin. Установленная версия Path и её профиль не используются.
6. Остановка сервера — Ctrl+C в этом окне.

Это desktop web renderer из актуальных модулей приложения. ZIP не является
установщиком Windows; проверка установленного приложения отдельно не выполнялась.

## iPhone: уже настроенный HTTPS

Для вашей текущей конфигурации Windows 11 → домашняя сеть → iPhone 12 Pro /
Safari iOS 26.6.1 можно использовать уже работающие сертификаты и правило 8443.

1. Сохраните открытые черновики на телефоне.
2. Скопируйте из нового ZIP папку **Path-Mobile** в
   `C:\PathMobile-Phone-Test`, подтвердив замену файлов. Итог:
   `C:\PathMobile-Phone-Test\Path-Mobile\index.html` и соседняя папка `domain`.
   Не создавайте вложенный `Path-Mobile\Path-Mobile`.
3. Не удаляйте `Trust`, `Tools` и закрытые сертификаты. В новом ZIP закрытых ключей
   нет. Если существующий HTTPS-сервер продолжает работать с этой папкой, его
   можно оставить запущенным.
4. Обновите в Safari тот же адрес: `https://192.168.1.66:8443/`.
5. Проверьте метку **SPORT A1**. На `/phone-check.html` идентификатор должен быть
   `path-sport-2026-11-11-a1`; повторите временный тест записи.

Если сервер остановлен, в обычном PowerShell запустите его снова по одной команде:

```powershell
Set-Location C:\PathMobile-Phone-Test
```

```powershell
$pathPrivate = Join-Path $env:LOCALAPPDATA "PathMobile-Phone-Test\Private"
```

```powershell
py -3 Tools\serve-phone.py --directory Path-Mobile --bind 192.168.1.66 --allow-lan --port 8443 --cert (Join-Path $pathPrivate "phone-cert.pem") --key (Join-Path $pathPrivate "phone-key.pem")
```

Эти IP/порт взяты из уже работающей настройки в переписке. Если адрес компьютера
или телефона изменился, сначала сверяйте текущую сеть и имеющееся правило;
переустановка доверия и обход предупреждения сертификата не требуются для обычной
замены файлов. Базовый ручной HTTPS-процесс описан в
`docs/mobile/phone-test/ACCESS.md` исходников. Сервер должен оставаться включённым.

## Сквозной сценарий

1. Создайте программу «Sport test» и два именованных шаблона A/B. Открытие этих
   экранов не должно добавлять событий в Calendar.
2. В A откройте Add exercise. На телефоне выберите Pull-up, Push-up, Hollow body
   hold и упражнение с весом; до «Добавить N» шаблон не меняется. Cancel отменяет
   временный выбор. На desktop плюс добавляет сразу, библиотека остаётся открыта;
   существующий Undo отменяет добавление.
3. Настройте число подходов, цель и отдых. У упражнения с весом проверьте два
   отдельных поля — повторы и вес. Явное Duplicate создаёт новую позицию.
4. Измените порядок через ручку или «Выше/Ниже». Обновите страницу и проверьте его.
5. Запланируйте тренировку и откройте Calendar. Перенесите её из Sport: должен
   остаться один прежний event ID. Плановый снимок не меняется от правки шаблона.
6. Начните тренировку, запишите один реальный подход и повторите нажатие. Запись
   должна быть одна. Проверьте отдых: пауза, продолжение, пропуск и +время.
7. Введите следующий результат, выйдите и вернитесь; затем обновите страницу.
   Ввод, сессия и рассчитанный по времени отдых должны восстановиться.
8. Завершите частично выполненную тренировку. В истории должны быть только
   записанные подходы, пометка неполного выполнения и прежние названия/единицы.
9. Измените исходный шаблон и проверьте неизменность прошлой записи.
10. Повторите в RU/ES, с длинным названием, при повороте, с клавиатурой и
    Settings → Accessibility → Motion → Reduce Motion на телефоне.

Отдельно: Upper → вручную исключить Biceps → включить Pull. Biceps остаётся
исключённым. Четыре группы без областей карты доступны списком. Scapular pull-up
имеет честный placeholder. Не оценивайте мышечное восстановление по подсветке.

## Desktop-test на телефоне

Откройте тот же origin с `?desktop-test=1`, создайте новую синтетическую копию
через существующую панель Desktop test mode. Повторите Sport-сценарий и экспорт.
Это отдельное хранилище `path-mobile-desktop-test-v1`; обычное мобильное состояние
не импортируется и не изменяется. Экспорт сохраняет полный canonical checkpoint.

Новые Sport v4 данные проверены на совместимость с обновлённым desktop-кодом
этого пакета. Старые неизменённые релизы могут не понимать новые измерения.
Синхронизация с установленным пользовательским Path этим этапом не подключается.

## Сохранность и границы проверки

Данные сохраняются в браузере по origin. Прежний HTTPS origin сохраняет прежнее
мобильное хранилище; другой порт/браузер создаёт отдельное. Локальные записи и
коммит не заменяют внешнюю резервную копию. Сохраните экспорт в отдельную папку.

Уже открытая страница умеет сохранять локальные изменения без сети. Холодный
офлайн-запуск, PWA, фоновый звук и исполнение JavaScript в фоне iOS не заявляются.
Для повторного открытия страницы нужен доступный сервер. Автоматизация Chromium
не подтверждает физические клавиатуру, safe areas и фон Safari — проверьте их
владельцем на телефоне и приложите build ID, шаги и запись при ошибке.

## Исходники, Git bundle и контрольные суммы

Для обычной проверки достаточно готового ZIP. Остальные файлы нужны для
сохранения и восстановления результата вне этой среды:

- `path-sport-alpha-source.tar.gz` — все отслеживаемые исходники desktop/mobile,
  общий domain, ассеты, тесты и документация. Распакованная папка — `path-sport`.
- `path-sport-alpha.bundle` — история локальной feature-ветки. Для восстановления
  нужен Git for Windows; эта команда создаёт новую локальную папку и ничего
  не отправляет в GitHub:

```powershell
git clone -b feature/path-mobile-alpha .\path-sport-alpha.bundle C:\Path-Sport-Source
```

Внутри восстановленных исходников `py -3 build.py` собирает desktop в
`preview\dist`, `py -3 mobile\build.py` собирает mobile в `mobile\dist`.
Python нужен для сборки; Node/Playwright нужны только при запуске тестов.
Файлы `BUILD.txt` и `DELIVERY.json` указывают точный HEAD. `SHA256SUMS` содержит
SHA-256 трёх основных файлов. В PowerShell вычислите сумму скачанного файла и
сравните со строкой в manifest:

```powershell
Get-FileHash .\path-sport-local-test.zip -Algorithm SHA256
```

Сохраните ZIP, source, bundle и SHA256SUMS в отдельное место. Нахождение их в
чате или локальный коммит не подтверждают внешнее резервное копирование.
