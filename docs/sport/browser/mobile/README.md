# Проверка Sport в мобильном браузере

Воспроизводимый прогон после `python3 mobile/build.py`:

```sh
node mobile/tests/sport-package-browser.cjs
```

Нужны уже установленные Playwright, `/usr/bin/chromium` и `ffmpeg`. Проверка не
устанавливает зависимости, не запускает сервер и не открывает сетевой доступ.
Запросы к синтетическому адресу `https://path-sport.test` выполняются чтением
локальных файлов из `mobile/dist`; все остальные запросы блокируются.

`verification.json` содержит фактические результаты, ошибки, время прогона,
версию браузера и SHA-256 проверенного `sport-ui.mjs`. Каждый сценарий запускается
с новым изолированным профилем и синтетическими данными. Два режима проверены
отдельно: обычное мобильное хранилище и desktop-test с настоящим адаптером.
В desktop-test обычный мобильный ключ содержит контрольную строку; проверяются
нулевые обращения к нему, сохранность неизвестных полей и экспорт через реальный
desktop-валидатор.

Основная цепочка создаёт программу и шаблоны A/B, добавляет упражнения в порядке
выбора, проверяет явное дублирование и изменение порядка с сохранением IDs после
перезагрузки. Затем создаётся и переносится одно событие Calendar, из него
возобновляется та же сессия. Проверяются сохранение черновика, фактические
повторы, дробные секунды и отдельные вес/повторы, отдых, пауза, продолжение,
двойное нажатие и частичное завершение. История содержит только записанные
подходы и неизменный снимок; последующее изменение шаблона её не меняет.

Принудительные ошибки записи проверяются при создании программы и шаблона,
пакетном добавлении, планировании, начале тренировки, записи подхода и завершении.
При ошибке сохранённые байты не меняются, введённые значения и временный выбор
сохраняются, повтор не создаёт дублей. Отдельный сценарий проверяет конфликт двух
вкладок с незавершённой формой.

Отдельный сценарий создаёт две desktop-копии с одинаковыми IDs активной сессии
и подхода. Ошибка записи только черновика первой копии блокирует переключение;
`7.` и `42,` остаются в форме. После Retry они сохраняются только в первой
копии. Во второй поля пусты, а выход из её сессии не записывает старые значения.
Сбой намеренно не запрещает обычную запись выбора второй копии: так проверяется
именно защита переключения, а не случайная блокировка всего хранилища.

Дополнительные проверки включают полный каталог, EN/RU/ES-поиск, избранное,
пользовательское упражнение, пустой результат, честный placeholder для Scapular
и для отсутствующего SVG, 19 групп мышц и сохранение ручных исключений из
пресетов. Сенсорные события Chromium проверяют изменение порядка ручкой и
обычную прокрутку содержимого без случайного изменения порядка.

Матрица: EN/RU/ES, ширины 320/360/390/430 CSS px в обоих режимах; отдельный
landscape 844×390. Проверяются отсутствие горизонтального переполнения страницы,
области действий не меньше 44×44 px, локальный Manrope, читаемый вес небольших
элементов, возможность прокрутить нижнее действие выше навигации и reduced motion.
Уменьшение `visualViewport` моделирует доступную высоту при клавиатуре; это
проверка геометрии приложения, а не настоящей клавиатуры iOS.

Скриншоты — реальные состояния браузера. `*-catalog-*-320/390.png` показывают
верх экрана, а `*-catalog-selected-*-320/390.png` — сами выбранные карточки.
`*-workout-overview-390.png` показывает тренировку с обычным коротким названием;
`*-workout-*-320/390.png` намеренно проверяет длинное название. Отдельные
`*-workout-fields-*` и `*-weighted-workout-*` показывают поля ввода.

`mobile-main-chain.mp4` записывает сценарий обычного мобильного хранилища в
Chromium с обычным motion: подбор → настройка → Calendar → запись/ошибка/повтор → выход и
восстановление → отдых → частичное завершение → история. Интервалы между
кадрами сохраняют фактическое время; файл не ускорен. Это автоматические
действия, а не запись взаимодействия человека на телефоне.
Для воспроизводимости Date фиксируется; проверка паузы переводит тестовые часы
на 30 секунд. Временная шкала видеозаписи при этом остаётся фактической.

iPhone 12 Pro, Safari/iOS 26.6.1, настоящие safe areas, системная клавиатура,
приостановка приложения ОС и установленная Windows-версия этим прогоном не
проверены. Он также не доказывает установку PWA, уведомления или холодный
офлайн-запуск.
